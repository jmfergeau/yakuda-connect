________________________________________________________________________________
 1. VERSION SETZEN
________________________________________________________________________________

cd ~/Schreibtisch/projects/Yakuda-connect/yakuda-connect

python3 scripts/bump_version.py 1.2.8

Das Skript pflegt DREI Stellen gleichzeitig:
  core/version.py           VERSION = "1.2.8"        <- Quelle der Wahrheit
  core/main.py              APP_VERSION = "v1.2.8"   <- Anker fuer alte Clients
  packaging/aur/PKGBUILD    pkgver=1.2.8, pkgrel=1

Die Zeile in core/main.py sieht nach Ueberbleibsel aus, ist aber Absicht:
Der Update-Checker aller Clients bis v1.1.4 laedt core/main.py von GitHub und
sucht darin per regulaerem Ausdruck nach genau dieser Zeile. Faellt sie weg,
melden alle installierten Altversionen fuer immer "aktuell".

VON HAND, das Skript macht das NICHT:

  CHANGELOG.md              neuer Block "### 🚀 v1.2.8" GANZ OBEN
                            mit "#### 🇩🇪 Deutsch" und "#### 🇬🇧 English"

  config/games.json         "info": { "version": ..., "last_updated": ... }
  config/tools.json         dito
                            -> NUR anfassen, wenn sich die jeweilige Datei
                               inhaltlich geaendert hat. Das sind DB-Versionen,
                               keine App-Version; sie duerfen hinter der
                               App-Version zurueckbleiben.

Kontrolle:

python3 scripts/bump_version.py --check --expect 1.2.8

git push origin main

git tag -a v1.2.8 -m "v1.2.8"

Tag-Format ist v<version> mit kleinem v — die PKGBUILD baut die Download-URL
daraus zusammen. Ein Tag ohne v findet updpkgsums nicht.

 5. AUR AKTUALISIEREN
________________________________________________________________________________

Erst hier, nie frueher: updpkgsums laedt den GitHub-Tag herunter.

__ PKGBUILD spiegeln

cp ~/Schreibtisch/projects/Yakuda-connect/yakuda-connect/packaging/aur/PKGBUILD \
   ~/aur/yakuda-connect/PKGBUILD

__ Bauen und testen

cd ~/aur/yakuda-connect
sudo rm -rf pkg src
rm -f *.pkg.tar.zst *.tar.gz          # sonst wird der alte Stand installiert

updpkgsums                            # ersetzt sha256sums durch den echten Wert
makepkg -si                           # Deps liegen alle in extra/
                                      # (python, pyside6, python-setproctitle)

cd ~ && yakuda-connect

Beim Test: startet es? Icon im Menue? Prozessname in btop?
Unten rechts muss v1.2.8 stehen — daran siehst du, ob wirklich der neue
Stand installiert ist und nicht der alte aus dem Cache.

__ Hochladen

cd ~/aur/yakuda-connect
makepkg --printsrcinfo > .SRCINFO     # PFLICHT nach JEDER PKGBUILD-Aenderung
git add PKGBUILD .SRCINFO             # NIE git add -A
git commit -m "Update to v1.2.8"
git push origin master                # AUR nutzt master, das Projekt main


________________________________________________________________________________
 WENN ETWAS KLEMMT
________________________________________________________________________________

updpkgsums gibt 404
  -> Der GitHub-Tag existiert noch nicht. Schritt 3 zuerst fertig machen.
     Gegenpruefen: git ls-remote --tags origin | grep v1.2.8

.SRCINFO vergessen
  -> AUR lehnt den Push ab. makepkg --printsrcinfo > .SRCINFO, neu committen.

Falscher Ordner
  -> Der AUR-Push geht NUR aus ~/aur/yakuda-connect. Die PKGBUILD unter
     packaging/aur/ im Projekt ist nur die Kopie zum Mitversionieren.
     (Der Kommentarkopf der PKGBUILD nennt faelschlich ~/yakuda-connect —
     beim naechsten Anfassen mitkorrigieren.)

pkgver mit Bindestrich
  -> 1.2.8 ist sauber, ein Alpha hiesse 1.2.8_alpha mit UNTERSTRICH.
     bump_version.py weist einen Bindestrich von sich aus zurueck.

Branch verwechselt
  -> Projekt: git push origin main.  AUR: git push origin master.

"ist aktuell -- ueberspringe Erstellen" / Berechtigungsfehler beim Bauen
  -> Reste vom letzten Lauf: sudo rm -rf pkg src; rm -f *.pkg.tar.zst *.tar.gz

Erfundene depends
  -> Jeden neuen Paketnamen mit  pacman -Si <name>  pruefen.
     Harte Abhaengigkeiten sind genau drei: python, pyside6,
     python-setproctitle. Alles andere (pactl, adb, pkexec, git, yay,
     flatpak, ...) sind externe PROGRAMME und gehoeren unter optdepends,
     nicht unter depends und nicht in die pyproject.toml.

Alte Clients melden kein Update
  -> Steht APP_VERSION = "v<neu>" noch in core/main.py? Siehe Schritt 1.
     Und: Release nicht als pre-release markiert?

App startet nach dem AUR-Update mit alter Version
  -> Alter Build im Cache. pkg/ und src/ loeschen, makepkg -si wiederholen.
